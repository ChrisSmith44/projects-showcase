Selected projects

Building useful software with clear systems behind it

These projects explore two different engineering challenges: making AI-assisted work more evidence-based and repeatable, and helping people compare the longer-term costs of car ownership.

Harness Factory

Harness Factory develops a portable delivery kit that helps teams give AI coding agents project-specific knowledge, workflows, and checks. Its central design idea is to keep reusable harness structure separate from the domain knowledge and rules that belong to each adopting project.

  • Python tooling
  • AI-assisted engineering
  • Project knowledge
  • Installable delivery kit
  • Checks and workflow design

Intent and design

The factory gathers and evaluates practices for AI-assisted engineering, then packages selected tools and structure for use in another repository. The delivery is designed to be installed locally in a project, with its knowledge and project-specific content remaining under that project's control.

How the delivery works

The kit is downloaded and unpacked outside the target repository. The maintainer can first preview the install plan, then apply it from the repository root and review the resulting changes before committing. The documented setup uses Python and the standard library for installation; it does not install software globally or fetch dependencies as part of the described install.

Why it has potential

Agent behavior and LLM wiegths are limited when it comes to specific domains, especially outside of pure software development. Agentic accuracy and efficiency wastly improves when it reflects a project's terminology, constraints, and review practices. A deterministic environment around the agetn harness that combines knowledge, checks, and repeatable workflows offers a practical way to bring agentic development work to a sustainable and cost-efficient level.

Released delivery kit — v1.2.0

  • Outer-Harness kit, building on top of vendored agent harnesses for engineering projects that are advancing for agentic AI integration onto their development processes.
  • Lightweight offline 4 layer agent memory system Working/Episodic/Semantic/Procedural
  • Deterministic verificaiton mechanisms built on LLM-Wiki and OKF v2.0.
  • Agent workflow with deterministic starting and closing mechanisms for user-agent & multi-agent sessions

Possible future directions

The roadmap discusses ideas such as a eval system, secutiry system, multi-model system (LLM + decision model), optional trace capture to provide stronger evidence for the ledger, and more deliberate selection of which skills a harness carries. These are roadmap concepts, not claims about the released v1.2.0 kit.

What it demonstrates

The project reflects systems thinking and product discipline: defining ownership boundaries, making installation reviewable, validating artifacts, and distinguishing documented evidence from assumptions. It also shows how an internal toolchain can be shaped into a versioned, user-facing delivery.

Version scope: The listed delivery-kit capabilities describe v1.2.0. The roadmap presents future work as a plan without dates or a release commitment; the concepts above should not be read as confirmed v1.3.0 features.

Keelion

Keelion is a car-purchase decision-support application built around Total Cost of Ownership (TCO): the idea that comparing vehicles should account for more than their purchase price. The product direction combines vehicle selection, user-specific assumptions, cost analysis, and recommendations in a guided web experience.

  • React and TypeScript
  • Python and Django REST Framework
  • Decision support
  • Modular calculation engines
  • Automotive domain

Intent and design

The application is organized as a frontend connected to a backend API, with separate Python packages for TCO calculation and recommendation logic. The intended user journey is a guided sequence: choose cars, provide ownership assumptions, then review comparisons.

Main product ideas

  • Compare vehicles using ownership-cost categories, not only sticker price.
  • Tailor analysis to inputs such as mileage, ownership period, and budget.
  • Present side-by-side results and recommendations as decision support, with vehicle variants as part of the comparison.

Why it has potential

Car purchases involve meaningful trade-offs between upfront cost, running costs, and personal needs. A tool that makes assumptions visible and comparisons easier to understand could help users ask better questions before making a purchase.

What it demonstrates

Keelion shows product-oriented engineering across a user workflow, a typed web interface, API boundaries, and domain-focused calculation components. The repository also includes project and API documentation, helping make the intended architecture and development direction understandable.

Current stage: The repository documents a broader product vision, but its backend documentation identifies the TCO and recommendation API endpoints as stubs. The cost-modeling and recommendation concepts should therefore be understood as development work and product direction, not as a claim of a fully integrated, production-ready service.

A balanced engineering approach

Together, these projects show an interest in building systems that are understandable as well as useful: clarifying the problem, separating responsibilities, documenting decisions, and being explicit about what is implemented versus what remains a hypothesis or next step. Both projects are works in progress, and their potential depends on continued testing, feedback, and iteration.
